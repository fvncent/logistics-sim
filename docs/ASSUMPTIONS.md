# Modelling and structural assumptions

These are my assumptions, not measured data. Each one lives in config where possible and should be revisited during calibration.

| # | Assumption | Where | Added |
|---|---|---|---|
| A1 | Package layout is `src/vlsim/<area>/` rather than the spec's top-level `world/`, `engine/`, … dirs (avoids import-name collisions such as `engine` and `models`). Approved 2026-10-16. | repo | M1 |
| A2 | Depot coordinates are the spec's approximate values, unverified against a map source. | `config/network.yaml` | M1 |
| A3 | Dock doors: 12 (HAN), 10 (DAD), 14 (SGN), 4 at each depot. | `config/network.yaml` | M1 |
| A4 | Lanes are undirected: every listed lane runs both ways (the spec draws feeders one way, but outbound delivery needs hub→depot). | `config/network.yaml` | M1 |
| A5 | S preset: 36 motorbikes, 8 vans, 6 trucks (50 total, as in the spec), 60 drivers, 200 merchants, 5,000 customers. M preset: 150/30/20 (200 total), 240 drivers, 800 merchants, 20,000 customers. Only the vehicle totals and shipments/day come from the spec. | `config/scale/` | M1 |
| A6 | Sim start 2026-10-01T00:00+07:00, seed 20261016. | `config/base.yaml` | M1 |
| A7 | Addresses use the post-2025 two-tier format (province, ward). `district` is nullable and left empty in the MVP. Ward names are synthetic labels from config, not real wards. The 2025 restructure (63→34 provinces, district level removed) is from memory and still needs checking. | M2 seed | M1 |
| A8 | Shipment states: CREATED, PICKED_UP, AT_ORIGIN_DEPOT, LINEHAUL_DEPARTED, AT_HUB (loops back to LINEHAUL_DEPARTED), AT_DEST_DEPOT, OUT_FOR_DELIVERY, DELIVERY_FAILED (reschedule to OUT_FOR_DELIVERY, max 3 attempts, then RETURNED), DELIVERED, RETURNED, EXCEPTION (damage, lost, address_unresolvable; can interrupt any stage). Confirmed by Vince 2026-10-16. EXCEPTION is terminal in the MVP (ADR 0005). | M4 | M1 |
| A9 | `telemetry.gps` events carry `schema_v` even though the spec's example omits it (the build prompt requires it on every event). | M5 | M1 |
| A10 | Tests use FastAPI 0.143.3 / Starlette 1.8.0 with httpx 0.28.1. Starlette's warning to switch TestClient to `httpx2` is filtered narrowly in `pyproject.toml`; `httpx2` is not adopted (decision 2026-10-16). Revisit when upgrading FastAPI. | `pyproject.toml` | M1 |
| A11 | TMS Postgres host port comes from `TMS_PG_PORT` (default 55432), read by both Compose and `vlsim.tms.settings`; `VLSIM_TMS_DSN` overrides it. | `.env.example` | M1 |
| A12 | Province per depot (post-2025 names, from memory; to verify): HAN Hà Nội, HPH Hải Phòng, VII Nghệ An, DAD Đà Nẵng, HUI Huế, NHA Khánh Hòa, SGN Hồ Chí Minh, BHA Đồng Nai, VCA Cần Thơ. `demand_weight` (share of customers, vans and motorbikes) is 3 for HAN and SGN, 2 for DAD, 1 for each depot. | `config/network.yaml` | M2 |
| A13 | ID formats (prefixed text, enforced by CHECK): `DP-HAN`, `CR-01`, `V-0001`, `D-0001`, `M-00001`, `C-0000001`, `A-00000001`, `O-…`/`S-…`/`T-…`/`CC-…`/`RM-…`/`INV-…` with 8+ digits, `RC-` with 6+ digits. Widths are minimums, so XL scale fits. The spec's examples `S-83110442`, `V-0192` and `D-2210` match. Whether shipment numbers look sequential or random is decided in M4. | `vlsim.tms.schema` | M2 |
| A14 | `orders.status` ∈ {CREATED, IN_FULFILLMENT, DELIVERED, RETURNED, EXCEPTION}; the spec names the column but not its values. | schema | M2 |
| A15 | `carriers.reliability_tier` ∈ {high, medium, low}. Seed carriers: CR-01 VietLink Fleet (own, high), CR-02 Partner Carrier A (high), CR-03 Partner Carrier B (medium), CR-04 Partner Carrier C (medium). The names are fictional. Planted patterns 2 and 5 attach to B and C in Phase 3. | `config/world.yaml` | M2 |
| A16 | `cod_remittances.status` ∈ {pending, confirmed, short}. | schema | M2 |
| A17 | `invoices(invoice_id, carrier_id, period_start DATE, period_end DATE, issued_at, total_vnd BIGINT, status ∈ {issued, paid, disputed})`; `invoice_lines(invoice_id, line_no, shipment_id → shipments, charge_type ∈ {base, fuel_surcharge, cod_fee, return_fee, other}, amount_vnd BIGINT ≥ 0)`, PK (invoice_id, line_no). Minimal tables for Phase 3. Credits and negative lines are not modelled. | schema | M2 |
| A18 | Column types: coordinates are DOUBLE PRECISION; `weight_kg` is NUMERIC(8,3); `cod_share` is NUMERIC(4,3); `capacity_kg` is INTEGER; `drivers.shift_start` is TIME (local UTC+7 time of day); `shift_hours_limit` is SMALLINT hours (1–16). All timestamps are TIMESTAMPTZ with no defaults. Shipments have no `created_at` column, because the spec lists none. | schema | M2 |
| A19 | `shipments.delivered_at` is set exactly when `current_status = 'DELIVERED'` (CHECK). `attempt_count` is 0–3. `trip_shipments.stop_seq` is ≥ 0 and not unique, so several parcels can share a stop. | schema | M2 |
| A20 | Seed world (all values in `config/world.yaml`):<ul><li>Two models per vehicle type: MB-110 60 kg / MB-125 80 kg, VAN-1T / VAN-1.5T, TRK-5T / TRK-8T, split 60/40 for motorbikes and 50/50 otherwise.</li><li>Trucks are based at hubs only.</li><li>Driver shifts start at 06:00, 08:00 or 14:00 (round-robin per depot), with a 10 h limit.</li><li>Merchant tiers are 5% enterprise, 20% mid and 75% small, with tiered `cod_share` ranges.</li><li>30% of customers get a second address.</li><li>Addresses scatter around the depot with sd 8 km (hub) or 4 km (depot).</li><li>Address quality is 80% good, 15% ambiguous (no house number) and 5% bad ("gần <street>").</li><li>Ward and street names are synthetic.</li><li>`created_at` falls up to 3 years (merchants) or 2 years (customers) before sim start.</li></ul> | `config/world.yaml` | M2 |
| A21 | Seeding a different preset into a database that already holds a larger one leaves the extra rows behind, because upserts never delete. Run `make clean` before switching presets. | `vlsim.tms.seed` | M2 |
| A22 | Floats in the seed (coordinates) are rounded to 6 decimals, so the stored values are stable. Whether numpy's normal draws are bitwise identical on arm64 and amd64 is not yet verified; the M6 cross-arch reproducibility check covers it. | `vlsim.world.build` | M2 |
| A23 | `event_time` is rendered with millisecond precision (`…:12.000+07:00`). The spec's example shows whole seconds; both are valid ISO-8601, and a fixed format keeps strings comparable. | `vlsim.engine.clock` | M3 |
| A24 | `event_id` = UUIDv5 over `canonical_json([kind, counter, content])` with namespace `uuid5(NAMESPACE_DNS, "sim.vietlink-express.invalid")`. Counters are kept per kind, such as a topic, rather than per entity, so the checkpoint does not grow without bound. | `vlsim.engine.ids` | M3 |
| A25 | Checkpoint retention: newest 5 (`keep`) in the SQLite store; checkpoint cadence comes from `checkpoint.interval_sim_minutes` (60). | `vlsim.engine.checkpoint`, `config/base.yaml` | M3 |
| A26 | The config fingerprint passed to the engine will be a hash of the canonical loaded config (wired up in M4/M6). The M3 tests use fixed strings. | `vlsim.engine.core` | M3 |
